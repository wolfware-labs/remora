# Remora Implementation Roadmap

> Companion to **`docs/design/remora.md`**. The spec defines *what* Remora does; this roadmap orders the work, states what each milestone must deliver, and how to prove it.

---

## How to use this document

- Work milestones **in order**; each builds on the previous ones. M0 freezes the contracts, M1 is a walking skeleton on all three OSes, and every later milestone deepens one area.
- Every deliverable has an ID (`R2.1`) used in issues, branch names and commit messages. Spec references look like `§8.4`; decision references look like `D-21`.
- Each deliverable is one issue and one pull request: one owner crate (rarely two), its code and its tests. A deliverable split in parts uses letters (`R0.8a`, `R0.8b`).
- **Owns** names the module that implements a capability of §4. No other deliverable implements it; later ones list it under **Reuses**.
- **Blocked by** lists direct prerequisites only. No deliverable is blocked by a later milestone.
- **Decides** names the open questions of §21 that the deliverable settles. It confirms the default or changes it, and records the result in the spec.
- A milestone is **done** only when its *Exit criteria* pass in CI.
- **Spec-first rule:** the spec, its golden files and its test vectors are the oracle. Any behaviour change updates `docs/design/remora.md` and the affected files under `testdata/` **in the same change**, before or with the code. If you find yourself deciding behaviour in code, stop and write it into the spec first.
- **`[verify]`** marks third-party behaviour (Claude Code, an OS, a library) that a test or a manual check must confirm before code relies on it (§1.4).

### Release lines

| Line | Milestones | Meaning |
|---|---|---|
| **Skeleton** | M0-M1 | Records and rewinds a Claude Code session on Linux, macOS and Windows. Not released. |
| **v0.1** | M0-M7 | First public release: GitHub Releases, crates.io, Homebrew tap, winget. |

| Layer | What | Deliverable |
|---|---|---|
| **Test kit** | Trees, dated fixtures, temporary data directories, hermetic `Env` values, the manual clock, guards | R0.10, R1.28 |
| **Golden files** | Journal vectors, wire messages, manifests, settings, service definitions, CLI JSON, format fixtures | R0.12, R0.14, R0.15, R1.6, R1.25, R4.7a, R5.4 |
| **Conformance** | Every snapshot and restore behaviour through `Snapshotter` on `REMORA_TEST_FS` | R1.9 |

| **Host drift** | Real `claude -p` run, weekly | R1.29 |

Tests for a behaviour live in the deliverable that builds it. Shared harnesses have their own deliverables, listed above.

## M0: Foundations

**Goal:** freeze the contracts and the filesystem core before any feature. The workspace and its layering check, the lint policy, CI on three OSes and on real filesystems, the `remora-fs` safety core with its `sys` module, the test kit, and every wire and on-disk type of `remora-types` with golden tests. Nothing here records a project; a test harness exercises all of it.

**Spec:** §3.2, §3.5, §4, §5.1, §5.3, §5.4, §5.5, §5.6, §5.8, §5.9, §6.2, §6.3, §6.4, §8.4, §10.3 to §10.6, §10.8, §10.11 to §10.13, §15.5, §17.1, §17.4, §17.5, §18.1, §18.2, §18.4.

### Exit criteria
- `ci` is green on Linux, macOS and Windows; the `fs` job is green on ext4, btrfs and XFS; the ReFS Dev Drive is created on the Windows runner.
- `xtask layers` passes on the workspace and fails on the forbidden edge and feature fixtures.
- Every `sys` function has a passing unit test on each OS where it compiles.
- On every runner and filesystem, no file or directory created by `remora-fs` is observed with group or other access, and no write follows a symlinked component.
- `xtask golden --check` and the journal vectors pass; a changed vector byte fails CI.

## M1: Walking skeleton

**Goal:** a Claude Code turn is recorded on Linux, macOS and Windows, and `remora log` and `remora rewind N` work, with a safety snapshot taken first. Every layer exists in its simplest correct form: plain copies, a signed journal without head checkpoint or `verify`, a daemon the hook starts on demand, first-page listings, and no retention.
